# LinkedIn Draft: Azure Security Posture Review

I completed a documentation-first Microsoft Azure security posture case study focused on IAM, Azure RBAC, access governance, and cloud misconfiguration risk.

The simulated review covered:

- Broad Owner and Contributor role assignments
- Stale user and service principal access
- Least-privilege and privileged access concerns
- Storage account exposure
- Network security group risk
- Diagnostic logs and audit logs
- Defender for Cloud-style recommendations
- Conditional Access and MFA considerations
- Incident response escalation criteria

My final analyst recommendations prioritized narrower Azure RBAC scope, recurring access reviews, time-bound privileged access, stronger logging and alerting, resource ownership, and controlled remediation of exposed cloud resources.

The key lesson was that cloud security posture management is not only about finding technical misconfigurations. It also requires clear ownership, access governance, evidence boundaries, practical risk review, and remediation that authorized teams can validate.

This was a simulated lab/case-study project. It did not involve a production tenant, real customer data, or production change authority.
